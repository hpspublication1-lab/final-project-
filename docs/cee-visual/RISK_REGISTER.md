# Risk Register

Likelihood and impact are judged from the evidence in `FEATURE_INVENTORY.md`, on a scale of Low, Medium, High. "Owner" is the role that must act; for most items that's the platform owner, because the action needs access or a decision I don't have.

| ID | Risk | Likelihood | Impact | Evidence | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| R01 | New migrations fail or damage data because the repo's migrations don't match live | High | High | Live lacks `program_type`; `chapters` columns differ (`CURRENT_ARCHITECTURE.md` §5) | Baseline from a live schema dump; additive `cee_*` tables only; dry-run on staging; reversible down-migration for each | Owner (dump), engineering | Open: needs dump |
| R02 | Tests and previews write to production data | High | High | Vercel previews use the production Supabase project | Separate staging project; preview env vars point to it | Owner | Open |
| R03 | A student reads draft or unreviewed visual content | Medium | High | Existing content is published by boolean flip (`AdminQuestionsClient.tsx:435`) | New tables have row security on with no client policies; students read only through server routes that return published snapshots; test CEE-004 | Engineering | Designed |
| R04 | A malicious GLB or SVG reaches students (XSS, decompression bomb, external fetch) | Medium | High | SVG accepted into a public bucket (`20260715050000_admin_uploads.sql:13`); validators unused (`uploadValidation.ts:62`) | Private quarantine; size and type limits; magic bytes; glTF validation with external URIs rejected; SVG rasterised or sanitised; malware scan; publish blocked until all pass | Engineering, owner (scanner) | Open: scanner not chosen |
| R05 | Cross-program leakage (IELTS/IOE content in CEE) | Medium | High | Ownership is inferred from names today (`courseIds.ts:155`) | Visual subsystem stores program and syllabus explicitly on every node; mappings are explicit rows; tests for Biology editor vs IELTS/IOE | Engineering | Designed |
